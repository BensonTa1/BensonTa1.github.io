2. Installation of the PDK

  This section will guide you to install the PDK into the design environment
  step by step and help users to set up their environment properply.

  [PDK owner]

    Step A: Download the PDK archive from TSMC website.

    Step B: Logon into the computer as the owner who will own and maintain the
            PDK.

    Step C: Choose a directory that are exported to all client machines to
            install the PDK.

    Step D: Install the PDK by execute "pdkInstall.pl" script and follow the
	    instructions displayed on screen step by step. If there is Perl/Tk
        in your environment, the command "pdkInstall_gui.pl -gui" can invoke
        a Perl/Tk GUI to install the PDK.

    Step E:(optional) After installing, the 'Techfile' directory can be removed. 

    ***Only the owner who will maintain the PDK has the read,write and execute
    permission. Other users will have only read and execute access***.


  [PDK users]

        In the client parts(the PDK users),there are also some procedures to be
    followed to set up the environment properply.

    Step 1: Logon into the computer as the user that will use the PDK to design
            a Project (circuit).

    Step 2: Setting the environment variable "CDS_Netlisting_Mode" to "Analog"
            and "CDSHOME" to Cadence DFII installation path.

		setenv CDS_Netlisting_Mode "Analog"
		setenv CDSHOME <Cadence DFII installation path>

    Step 3: Make a directory for your design project.
		EX: %mkdir ~/my_circuit
		    %cd ~/my_circuit

    Step 4: Create a new library for your design and add the PDK library into
            your reference path by adding the following line in your "cds.lib"
	    file located in the working directory.

	        INCLUDE <pdk_install_directory>/cds.lib

      add these two diodes in their schematic to make the LVS clean.

5. CDF parameters

   - MOSFETS 
	? Multiplier - number of Parallel MOS devices 
	? Model Name - spectre model name (non-editable) 
	? Length (M) - gate length in meters 
	? Total Width (M) - gate width in meters (sum of all fingers) 
	? Finger Width - width of each gate finger/stripe 
	? Fingers - number of poly gate fingers/stripes used in layout 
	? Threshold -? finger width at which to apply device folding of the layout. 
	? Apply Threshold -? button to apply threshold or not 
	? Gate Connection -? allow shorting of multi-finger devices and additionof 
			    contact heads to gate ends. 
	? S/D Connection -? allow shorting of source and/or drains on multi-finger 
			    devices. 
	? S/D Metal Width -? width of metal used to short sources/drains. 
	? Switch S/D -  source is defined as left-most diffusion region and 
		       alternating regions to the right. Pins are not automatically permuted and 
		       can be switched using this parameter. 
	? Bodytie Type -? Nnne, Detached, or Integrated (butting source). 
		- For Detached, user may select Left, Right, Top, and/or 
		  Bottom to specify the located of bodyties. Selection of all 
		  four creates a guardring. 
		- For Detached, the user may specify Tap Extension (in 
		  microns) which sets the distance from the bodytie to the 
		  device. Maximum distance is 100 microns. 
		- For Integrated, the user may select Left or Right for a device 
		  with an odd number of fingers (1, 3, 5, ?). The user may 
		  select Left and Right for an even fingered device. 
	? Drain diffusion area, etc -? several simulation parameters are presented. 
	     The area and perimeter parameters are calculated and netlisted in 
	     accordance with the foundry models.

    - Resistors 
	? Resistance - Resistance value used for simulation 
	? Contact Resistance - (foundry model includes this) 
	? w (M) - resistor width in meters (non-editable) 
	? l (M) - resistor length in meters (non-editable) 
	? Entry Mode - Parameter entry mode - cyclic (Length&Width, Res&Width) 
	? Rho - resistor layer sheet rho (non-editable) 
	? Model name -? Spectre model name (non-editable) 

    - BJT
	? Model name - Spectre model name (non-editable) 
	? Emitter Area -? cyclic of the area of the emitter (microns) 
	? Multiplier - Number of Parallel Bipolar devices 
	? Estimated Operating Region -? Cyclic of Spectre model operating region 

    - Diodes
	? Model name - Spectre model name (non-editable) 
	? Device Area - Calculated junction area in meters squared (non-editable) 
	? Multiplier - Number of Parallel Diode devices 
	? Length (M) - diode length in meters 
	? Width (M) - diode width in meters 

    - Capacitors
	? Capacitance -? Unit capacitance corresponding to the length and width 
	? Total Capacitance -? Total capacitance ? m * C (non-editable) 
	? Capacitance Entry Mode -? Parameter entry mode - cyclic (Capacitance, 
				   Cap & Length, Cap & Width, Length&Width) 
	? Length (M) - Capacitor length in meters (non-editable) 
	? Width (M) - Capacitor width in meters (editable if spec is l&w) 
	? Width Per Finger -? Width of each finger (non-editable) 
	? Number of Fingers -? Integer number of capacitor fingers 
	? Top Plate Connection -? Connect poly fingers 
	? Poly Contact Head -? Add Poly/Contact/Metal heads to top plate 
	? Drain/Source Connection -? Sheet, Strips, or None. Sheet may cause 
		wide-metal violations on larger devices. Use Strips in this case. 
	? Multiplier - Number of Parallel capacitor devices 
	? Model Name -? Spectre model name (non-editable) CAPACITOR ADD INSTANCE FORM

	Number_of_Fingers - Number of poly gate stripes used in layout

9. Known problems

 9.1 Schematic Capture

Issue: Resistor callbacks for the non-silicided resistors can potentially give
       slightly incorrect values for resistance.
Solution: Displayed values of resistance are not used in circuit simulation. Only
       width and length are used. The most accurate source of electrical values
       such as resistance and capacitance are found through simulation.

Issue: Callbacks for the inductors can potentially give
       slightly incorrect values for inductance.

 9.2 Simulation 

Issue: Resistors in an av_extracted view netlist with default width and length.
Solution: Please see the detailed solution below under the Assura RCX KP&S. 

Issue: In most updated design rule, TSMC not provide pmos in PW varactor but pmoscap_33
       still exist in SPICE model card.
Solution: Remove pmoscap_33 to DO_NOT_USE categories.
       
Issue: There doesn't have pmos in PW varactors in PDK but model does.
Solution: In most updated design rule, TSMC not provide pmos in PW varactor.

 9.3 Layout 

Issue: Abutted dog boned mosfets have non-aligned implant. 
Solution: When abutting two dogboned devices, the implant rectangles of each 
       device do not have the same top and bottom locations. No DRC violation
       occurs but on implant overlap is larger than the minimum allowed. 

 9.4 DRC 

Issue: Large moscaps and diodes violate metal slotting rules. 
Solution: This condition cannot be reliably resolved by automated means. This 
       should be resolved by the user, taking desired performance issues into 
       account. The moscap pcells allow the user to select the drain/source 
       connection as a series of metal 'strips' instead of a single 'sheet'. 

Issue: Set huge length and arrayY or width and arrayX of "mimcap" and "mimcap_mis" 
       at the same time might cause DRC violation - "CBM.W.2". This condition is 
       not restricted due to flexable usage of user.

 9.5 LVS

Issue: Set "multiplier" and "connection" of resisters may cause "Assura LVS" issue 
       due to precision problem.

 9.6 RCX 

Issue: Resistors in an av_extracted view netlist with default width and length. 
Solution: Please run the tsmc13_fixAv_Extracted() skill routine on the library 
       or cell. This will correct the property types from float to string which will 
       correct the netlisting problem. For example, 
       In the CIW enter: tsmc13_fixAv_Extracted("myDesignLib")
       Action: this will scan the myDesignLib library looking for av_extracted 
       cellviews. If found, they will be opened and the property types for all 
       resistors will be changed to string. 
       To perform this on a single cell: 
       In the CIW enter: tsmc13_fixAv_Extracted("myDesignLib" "myDesignCell")
       Action: this will attempt to open the av_extracted view of the 
       myDesignCell cell and perform the actions described above. 

Issue: After running RC extraction, I found the 'nrd' and 'nrs' (for MOS) were 
       different with the pre-sim netlist values.
Solution: The 'nrd' and 'nrs' values in pre-sim netlist (calculated by PDK) are
       calculated with the distance from S/D contact to gate(more accuracy) while
       they are calculated from S/D edge to gate in RC decks(due to tool limitation).
       Thus, the 'nrs' and 'nrd' values in pre-sim netlist are more accuracy than 
       post-sim netlist.
       
Issue: When running Assura/Calibre RC extraction with GDS flows, two issues may
       be found:
       a. The model names of 'rppolys', 'rppolyl', 'rnpolys' and 'rnpolyl' don't
           change with ressistor widths.
       b. The model name of BJT device is fixed to 'npn2/pnp2'.
Solution: This is due to the deck issue. For the poly resistors, the released RC
       decks can't tell these resistors with different widths. For BJT device,
       the RC deck can't tell the emitter size. If users use these devices in 
       their designs, please remember to modify the extracted netlist by hand.

Issue: When running Calibre RC extraction with GDS flow, the following models/devices
       should be manully modified: RNPOLYWO, RNPOLYL, RNPOLYS, RNWSTI, RPPOLYWO
       , RPPOLYL and RPPOLYS.
Solution: This is due to the RC deck issue. The Calibre RC deck doesn't extract
       reistor width and length for these devices.

Issue: When running Assura RC extraction with DFII flow, the BJT devices are
       netlisted out with incorrect model name.
Solution: This is due to the RC deck issue. Currently, the RC deck doesn't tell
       the BJT devices with their emitter size. Please manually handle it.

Issue: Assura/Calibre RC deck only support 1p6m and 1p8m w/i UTM metal scheme.

Issue: Run Calibre XRC in 64-bit mode can avoide the memory allocation failed of mimcap devices.
       Because 32-bit Calibre tool may result in address space issue in some cases.

10. Utilities
       In order to ease the use of this PDK, some utilities are provided below
    to help the users. ***Please remember to backup your designs before running
    this utilities(very important)***

 10.1 CDF update utility -- tsmc13rf_updateCDFs("Library_name")

   When changes are made to a device inside the PDK, these changes often affect 
circuit design which have already been created. For example, a sheet rho value may 
change on a resistor which affects the length of the device passed to the simulator 
and used to generate the layout. 
These parameters are not automatically updated in each of the designer's circuit 
libraries. A function has been written and included as a part of the PDK to complete 
the update to an existing library such that all modifications made to a PDK since a 
previous release are reflected in each of the circuit designs inside a library. 
There is a single argument to this fuction which represents the design library which 
is to be updated with the new CDF information. Once this routine has been run, all designs 
in the designated library will be in sync with the latest release of the PDK.
***Please note, however, that possible DRC and LVS violations may arise as a result of 
running this routine depending upon what changes have been made to the PDK***. For 
example, a sheet rho change as specified earlier could cause a resistor to 
shrink in length in the layout thus causing an open as far as LVS is concerned. 
Please be sure that you re-verify each design in simulation, DRC, and LVS to insure 
that no unintended modifications have been overlooked. 
The syntax for this function is as follows: 
In the CIW, 

     type 'tsmc13rf_updateCDFs(libName)'

for the library which you wish to operate on. 
For example, given a library named 'designLib', the proper syntax for this 
routine would be: 

     tsmc13rf_updateCDFs("designLib")    => update CDFs for all cells in "designLib" library
 or
     tsmc13rf_updateCDFs("designLib" "myDesign") => update CDFs for cell "myDesign"

Please be sure that the library name you choose to pass as an argument is 
present in the library manager window (i.e. - be sure that it is visible and 
located in your cds.lib file) 

 10.2 2T-resistors migration utility -- tsmc13rf_migrate_res2t_to_res3t("libName")
     From PDK V1.2P1 and later, the 2T resistors (rnhplus2T, rnlplus2T, rphplus2T
, rplplus2T, rnwellod2T) are not support anymore. We strongly recommand our
customers to migrate these devices to 3T resistors (more accuracy). Moreover,
the cell names for OD resistors(w/o salicide) are also changed after V1.2P1
(rnhplus -> rnplus; rphplus -> rpplus). In order to help our customers to 
migrate from the older version of PDK to this new one. We provide a utility
'tsmc13rf_migrate_res2t_to_res3t()' to support this function. The syntax
for using this utility is as follows:

 In the CIW, 

     type 'tsmc13rf_migrate_res2t_to_res3t("myDesingLib")'

 This utility will do the following things on all cell of your design library:
               Replacements:
                      rnhplus2T -> rnplus 
                      rnlplus2T -> rnlplus  
                      rphplus2T -> rpplus   
                      rplplus2T -> rplplus  
                      rnwellod2T -> rnwellod
                      rnhplus -> rnplus
                      rphplus -> rpplus
		      
 10.3 tsmc13rf_device_update(S_option S_libName S_cellName)
    This utility is provided to user to transit the device form Normal device 
to Mismatch device or reverse.
> S_option: It's a key word that use to decide which kind of device user want transition.
 	    If the input is "nor", the device will transit to Normal device. If the input 
	    is "mis", the device will transit mismatch device.("nor" or "mis") 	
> S_libName: The cell's libary name. 
> S_cellName: The cell that user want to transit.

Example: tsmc13rf_device_update("nor" "tsmc13rf" "LNA")

Note: This utility not support hierarchy structure and it only transit schematic view.
